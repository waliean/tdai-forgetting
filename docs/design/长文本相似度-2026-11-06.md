# 长文本相似度 — 2026-11-06

画布 D 的 D5。回答一个问题：4-gram shingle 对长文本稀释到什么程度，该换算法还是按长度分档。

结论先说：**换算法，用句子块覆盖率**。分档阈值实测误合并 9.4%，弃。

## 一、稀释有多严重

固定一个 100 字的前缀，让被比较的文档从 100 字长到 1200 字，每次都算 Jaccard：

| 被比较文档长度 | Jaccard |
|---|---|
| 100 | 1.000 |
| 200 | 0.506 |
| 300 | 0.352 |
| 400 | 0.273 |
| 600 | 0.196 |
| 800 | 0.154 |
| 1000 | 0.126 |
| 1200 | 0.111 |

掉得比线性还快：200 字就跌破 0.6，400 字已经低于 0.3。原因是集合大小随文本增长，而交集停在 100 字那一份上。

再验证 prompt 里那个说法——"两条 1000 字记录即使讲同一件事，只要各有 200 字不同，Jaccard 就会显著低于 0.6"。实测两条 600 字、各差 200 字的同事实文本：**Jaccard = 0.565**。0.6 的门槛会把它们判成不同。

所以这不是"阈值偏保守"，是**单个阈值在数学上不可能同时服务 70 字和 1200 字两种文档**。

## 二、两个方案在长文本语料上的实测

语料是 D2 的 `bench/corpus-long.ts`：60 组事实，每组一个 brief（约 540 字）和一个 full（约 1220 字，以 brief 正文开头）。真重复对 60 个，无关对 7,080 个。

判据按 prompt 定：**真重复召回率**与**误合并率**。

| 方案 | 真重复召回 | 误合并 | 召回 − 误合并 |
|---|---|---|---|
| 现状（Jaccard ≥ 0.7 + 长度比预过滤） | 0/60 = 0.000 | 0/7080 = 0.000 | 0.000 |
| 长度分档（<200: 0.6 / 200–600: 0.45 / >600: 0.35） | 60/60 = 1.000 | **664/7080 = 0.0938** | 0.906 |
| **句子块覆盖率 ≥ 0.8** | **60/60 = 1.000** | **0/7080 = 0.000** | **1.000** |

复现：`node bench/dilution.ts`。

### 现状为什么是 0 召回

两层，不是一层：

1. `findRedundancyClusters` 在算 Jaccard 之前有长度比预过滤：`min/max < threshold` 就跳过。brief 540 / full 1220 = 0.44，小于 0.7，**这一对根本没进入相似度计算**。
2. 就算跳过预过滤，同组 brief/full 的 Jaccard 在 0.493–0.632 之间，有几个在门槛上、有几个在门槛下，结果会是随机的。

第一层是 D2 报告里记的那个发现，第二层是本文第一节的曲线。

### 分档为什么误合并 9.4%

分档把长文本的门槛压到 0.35。而不同事实组之间最像的一对 full 是 0.484——**门槛压到 0.35 就切进了"不同事实"的分布里**。

这不是阈值没调好：想覆盖 brief/full 的 0.44 比值，门槛必须 ≤ 0.5；想避开无关对的 0.484，门槛必须 > 0.484。两个区间只差 0.016，任何分档方案都在这条缝里走钢丝。而且分档还要自己拍三个数（0.6 / 0.45 / 0.35），prompt 里也点破了："把阈值变成了三个拍的数"。

## 三、为什么块级覆盖率对

Jaccard 问的是"这两个的并集里共享多少"，分母包含长度差，所以长的那一方天然吃亏。

覆盖率问的是"`a` 的每一块能不能在 `b` 里找到对应"，分母只有 `a` 自己的块数，长度差被消掉了。而"同一事实的长短两版"恰恰就是**短版的每一句都出现在长版里**。

实现（`src/redundancy.ts`）：

- `splitBlocks`：按句末标点切块，丢掉 12 字以下的碎片。
- `blockCoverageOf`：对 `a` 的每个块，在 `b` 的块里找最大 Jaccard（块内用 3-gram），≥ `blockSimilarity` 记为命中；返回命中比例。
- 命中比例 ≥ `blockCoverage` 即判为重复。

默认：`blockMinLength = 400`、`blockSimilarity = 0.8`、`blockCoverage = 0.8`。

两个 0.8 语义不同，容易混：一个是"两句算不算同一句"，一个是"多少句算同文"。参数名分开写了。

## 四、落地点

`src/redundancy.ts` 的 `ClusterOptions` 加了三个字段，`findRedundancyClusters` 的两两比较按长度分流：

```
if (任一文档长度 >= blockMinLength) 走块级覆盖率，不做长度比预过滤
else                                走原 Jaccard + 长度比预过滤
```

**块级分支刻意跳过长度比预过滤**：brief/full 的 0.44 比值正是预过滤当初拒掉的那一对，这里再预过滤一次等于没改。

### 对短文本没有影响

- `synthetic`（p50 70 字）：`evictedShare` 0.3395，与 D4 前的量级一致，走的是 Jaccard 分支。
- `snapshot`（p50 328 字）：`evictedShare` 0，同样走 Jaccard。
- `longtext`：`evictedShare` 从 **0 变成 0.55**——60 组各归档一份。

`bench/run-bench.ts` 的数字一个没变（它用 `collapseDuplicates`，是窗口内去重，不走聚类）。

## 五、被否决方案的成本

**长度分档**：代码量最小（一个 `thresholdForLength()` 加去掉预过滤，约 10 行），比块级便宜得多。否决理由是数据：9.4% 的误合并，而且三个档位阈值本身就是新的拍数——D 这一整个画布的存在理由就是反对拍数。留下的成本是：下次语料换了还得重拍一次。

**simhash**（评估了但没实现）：64 位指纹，汉明距离判重，固定长度、天然不受稀释影响。但它是**集合相似度**的近似，对"短版全包含在长版里"这个具体的包含关系不敏感——两条文档的指纹由全部 shingle 决定，长版多出来的 680 字会把指纹推开，和 Jaccard 犯同一个错，只是幅度小些。真要用它找短版⊂长版，还得额外做一次滑动窗口。成本比块级高，效果没有证据说更好，所以没实现。

**minhash**：同样只近似 Jaccard，不解决包含关系，且需要固定数量的置换函数（实现不便宜）。否决理由同上。

## 六、代价与已知边界

1. **比较变贵。** 短文本仍是 O(1) Jaccard；块级是 O(|blocks_a| × |blocks_b|) 次块内 Jaccard。长文本语料 120 条、7,140 对，`sweep --describe` 从原来的 <200ms 涨到约 1.8s。还在可接受范围，但如果 L1 出现成千上万条长文本，这里会先炸。
2. **`minSimilarity` 混了两种量纲。** 块级对存的是覆盖率，Jaccard 对存的是 Jaccard，两者的 0.8 不是一回事。字段注释里写了，但没有把它们分开——只有簇内最小值这一个消费者，且只用于展示。
3. **保留哪一份没有考虑长短。** `pickLead` 按 pin → score → access → updated 选，brief 和 full 这几项全相同，于是留下的是排序里的第一个，也就是 brief。**结果是归档长版、保留短版。** 这不是 D5 能决定的（改 pickLead 是另一个决策），但要记下来：有人可能会期望保留信息更全的那一份。
4. **块切分按中文句末标点。** 英文的 `.` 没有切（`.split(/[。！？!?\n]+/)`），英文长文本会退化成"整段一块"，覆盖率就退化成对整段的比较。当前语料没有这个问题，换英文语料要补。
