# 方案设计（2026-10-26）

目标：给 tdai 的 L1 原子记忆补一层按价值淘汰的机制，可回滚、可审计、不改变 API 契约。

## 约束

方案不是从零设计，是在四条约束下做取舍：

1. **不能改 API 形状**。`score` 必须继续落在 `[0,1]`，返回条数不变，字段不删。
2. **不能丢召回**。任何"过滤"都可能让本来能找到的记忆找不到，而使用者无法察觉。所以排序可以改，取舍要单独决定。
3. **不能依赖 embedding 服务**。该服务在部署里是可选的，离线和降级场景都要能跑。
4. **必须能回答"为什么"**。一条记忆被淘汰，半年后要能从库里查出当时的分数和理由。

## 三个可选项的对比

| 方案 | 做法 | 优点 | 否决理由 |
|---|---|---|---|
| 换框架 | 用 mem0 / MemOS / MemoryBear 替换 tdai 存储 | 功能齐全，有现成遗忘 | 丢掉 L0 白盒溯源和三元组隔离；迁移成本高于加几列 |
| 打补丁到现有清理器 | 改 `LocalMemoryCleaner`，按分数删 | 改动最小，一个文件 | 硬删不可逆；`updated_time` 被 dedup 刷新，判据本身是错的 |
| **分层改造（采用）** | 排序层加衰减、存储层加状态、清理层加计划 | 每层可独立开关和回滚 | — |

关键在于把"离开可召回集"和"删除字节"拆成两个决策。前者可以自动做，可以随时反悔；后者需要人确认，因为它销毁证据。

## 分层

### 第一层：检索排序（src/l1-decay.ts）

```
multiplier = clamp( decay + 0.5 * usage , 0.3 , 1.5 )
```

- `decay = floor + (1 - floor) * 2^(-age / halfLife)`，`floor = 0.3`，`halfLife = 30d`
- `usage = 1 - exp(-access_count / 5)`
- `age` 优先取 `last_access_time`，退到 `updated_time`，再退到 `created_time`

为什么用乘法而不是替换分数：乘法保留原来的相关性序，只做加权。排在前面的还是原来那批，只是顺序变了。换成"分数 = 相关性 + 权重 × 新鲜度"会让一条毫不相关的刚写入记录挤掉高相关的老记录。

为什么地板是 0.3 而不是 0.1 或 0：mem0 用 0.3，含义是"最多压到三成"。压得更狠等于事实上的过滤，与约束 2 冲突。

### 第二层：pin 豁免（src/pin.ts）

见 README 的两级表格。这里补三个设计判断：

**为什么 metadata 优先于 priority**：显式声明的意图强于推断。`priority = -1` 是上游的历史约定，含义是"全局指令"，不是"永久记忆"，两者只是大量重叠。

**为什么非指令型的"永久"引用只给 extended**：一次迁移会把用户当年的请求原文搬进 episodic 记录，正文里就带着"永久记住"。把它当指令，等于让所有历史请求都免疫淘汰；完全不认，又会在用户预期上捅一刀。折中是延长半衰期，让它在几个月内缓慢下沉，而不是立刻或永不。

**为什么 review 列表默认应该是空的**：默认规则已经覆盖了全部 822 条里的永久性措辞（实测 0 条漏网）。这个列表是给"有人调低规则"和"出现新语料"准备的，不是常态输出。

### 第三层：淘汰计划与落库（src/planner.ts / src/applier.ts）

顺序：pin → 绝对阈值 → 冗余 → 配额。

- **绝对阈值**先于冗余：一条又老又重复的记忆，理由应该是"老了"，而不是"隔壁那条也在"。理由影响事后复核的判断。
- **冗余**先于配额：重复副本是最便宜的淘汰对象，先让它付账，配额才不会挤掉独有事实。
- **配额**跳过 pin。因此有效配额 = 配额 − pin 数，这件事写在 run 的 notes 里，不做静默修正。

落库全程在一个事务里：更新 `state`、写 `forgetting_audit`、写 `forgetting_runs`。`dryRun` 连审计表都不建。

### 第四层：访问证据（src/recall.ts）

两条写入路径，按运行位置选：

- `appendRecall`：检索时追加一行 JSON（fire-and-forget）。core 已经持有 WAL 连接，再开一个写入者只是白白增加锁竞争；追加文件便宜、有序、崩了也留得下。
- `foldAccessLog`：离线聚合，一个事务更新计数器。折叠成功后日志**重命名**而不是截断——如果进程死在重命名和提交之间，没折进去的数据还在盘上，可以手工重放。

## 门槛机制

`trackingCoverage < 10%` 时年龄项整体退出。这不是保守，是实测结论：在无访问数据的语料上强制衰减会掉 3.5 个点，而这种语料正是当前所有 tdai 部署的状态。

门槛是整批一起判定，不是逐条。逐条判定会让一次排序里混用两种策略，得出的顺序没有意义。

## 回滚

| 改动 | 回滚方式 |
|---|---|
| 检索衰减 | 传 `decay: undefined`，恢复纯 RRF |
| 淘汰计划 | 不执行 apply，或执行后 `UPDATE l1_records SET state='active' WHERE forgotten_time > ?` |
| schema 加列 | 列可留，旧代码不读即无影响 |
| 访问日志 | 删文件即停，计数器保留 |

没有不可逆操作。这是刻意的：一个不可逆的遗忘机制，第一次误判就会失去信任。

## 未做与理由

- **自动调度**：阈值该先被人工审几轮。定时任务在阈值未校准时等于放大器。
- **物理删除**：销毁证据，需要单独的人工确认流程，不属于自动策略。
- **L0 / L2 / L3 的淘汰**：四层语义不同。L0 是原始对话（证据），L2 是场景（结构），L3 是画像（提炼），不能套同一个分数。
- **双时间戳失效标记**：Graphiti 的做法值得借鉴，但需要 dedup 在合并时判断"新结论推翻旧结论"，这是 LLM 判断，成本和准确率都要先测。见实测报告的 supersede 实验。
