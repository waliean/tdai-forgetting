## 二、被评审推翻并返工的地方（三轮）

这块被三位独立评审判过三轮，返工清单比成果清单更有用：

1. **c3 的变异测试是假的。** 测试跑的是手抄的 SQL 常量，不是补丁真发的 SQL。所以"变异后测试变红"证明的是常量被改了，不是代码被改了。修法：测试从补丁文件里读 SQL 解析谓词，重跑变异后 4 条断言真的死了。
2. **c6 文档里的 7 与产物里的 17 对不上。** 改了 stub 判决规则却没重跑表格。
3. **stub 按请求序号判决。** 每个 CLI run 是新进程、计数器归零，于是 shadow 与 apply 判的是**不同的 17 对**（实测交集 0/17），而文档写着"同样 17 个判决"。
4. **重复 apply 写幽灵审计行。** UPDATE 带 `AND invalid_at IS NULL`，重跑时 `changes = 0` 却仍插 `invalidate` 行、仍报 `applied: true`。审计是本项目唯一的纠错手段，幽灵行会废掉它。
5. **gate 接受空值与负值。** `Number("")` === 0，于是 `--false-supersede-rate=`（未赋值的 shell 变量）被读成"测量 0%，闸门大开"，50 条记忆被写。同时 `-0.5` 也放行。
6. **`$&` 注入。** `tpl.replace("{old}", 正文)` 会把正文里的 `$&`、`$'` 当替换模式，把模板片段拼进提示词。语料 822 行里已有 1 行含 `$'`。
7. **文档给标注者安了没说过的话。** 引用 A2 的理由是编的。已改成逐字引原话。
8. **两个标注者标注者=实现者。** 补了第二位盲标者。

## 三、那个数不能信

LLM 判据的误标率有三个值，取决于拿谁当金标准：

| 金标准 | 误标率 |
|---|---|
| A1（实现者，AI） | 70.6%（12/17） |
| A2（盲标，独立 AI） | 88.2%（15/17） |
| 两者共识的 36 对 | 85.7%（12/14） |

三个都远高于 5% 门槛，所以 gate 拒绝 apply —— 方向是对的。

**但真正该读的是两位标注者的一致率：72.0%（36/50），Cohen's κ = 0.268。** 连"两条记忆是否构成取代"这个判断本身，两个独立判断者有四分之一对不上。拿 κ=0.27 的金标准去卡 5% 的门槛，卡出来的数字没有意义——**不是判据不够好，是任务本身的标注噪声比门槛还大**。

而且两位标注者都是 AI 代理，A2 与 A1 是同一个底层模型。所以 72% 不能外推为人类标注者之间的一致性。

结论：**这个门禁的机制可以信，5% 这个阈值在这份语料上不可信。** 要真用，得先让"什么算取代"有可复现的定义，或者把门槛改成相对口径（与基线判据相比不劣于 X）或分层口径（按 `type` / `scene` 分设阈值）。这是设计决策，没在本画布内擅自改。
