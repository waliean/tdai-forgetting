### 可召回性：在副本上验不了

`POST /v3/atomic/search` 对回退那条返回 0 条。**但搜从未归档的 active 记录同样是 0 条**，所以不是回退没生效：

```
[hybrid-vec] Embedding OK, dims=1024, searching top-15...
RESULT (strategy=embedding): returning 0 memories (scores: [])
```

向量数据在（`l1_vec_vector_chunks00` 4 MB ≈ 1024 条，`embedding_meta` 记 bge-m3/1024 维），但复制出来的库里 `sqlite-vec` 虚拟表命中不了；`node src/cli.ts coverage` 在同一副本上也报 `vector/0`。

**结论**：能验的是"回退的选择是对的"，不能验的是"恢复后检索得到"。后者需要一个向量检索正常的环境——生产容器本身，或者重建过索引的副本。

## 演练额外发现的两个真问题

### 1. 未知参数曾导致静默全量回退（已修）

演练第一步我打错成 `--rules`。脚本把所有以 `-` 开头的参数过滤掉，于是它被丢弃、`dryRun` 为 false，**一次打错就把整个 run 回退了**。审计表里当时出现 6 条 archive + 6 条 rollback。

已修：未知选项现在是 usage error（exit 1，零写入），回归测试 `an unknown option is a usage error, not a silent full rollback`。这条是这次演练最有价值的产出——如果没做容器演练，它会带着上线。

### 2. 容器运行中改库会让它的连接失效

第一次在容器跑着的时候改副本库，随后搜索返回 500 `disk I/O error`，重启才恢复。runbook 第五节原本写的是"撞 WAL 锁"，实际表现更彻底：不是等待，是连接坏掉。已改成"改库前停容器是必需步骤"。

## 没解决的

`acceptance` 的"恢复可召回"这半句仍未在生产环境验证过。建议在首次真实回退前，于生产容器上对一个无害记录做一次"归档→回退→检索"的闭环；或在副本上重建向量索引后再验。
