## 二、为什么不直接在 run-bench 上加参数

`run-bench.ts` 顶层直接 `void run(...)`，**`import` 它会把整个 benchmark 跑一遍**。sweep 需要它的评估函数，所以先得把函数与驱动分开。抽 `harness.ts` 而不是在 sweep 里复制一份，是因为"两套 precision 口径"正是本画布要防的那个失效：一旦复制，历史数字与新区间不可比，而且两边都还会打印出看着合理的小数。

搬移是逐字的，没有趁机改算法。验证方式是重构前后各跑一次 `run-bench` 并比对输出，三次（搬移 imports、删除函数体、抽出 `collapseDuplicates` 之后）结果逐字相同：

```
configuration precision@k  top1    dupShare  pinRecall  avgScore
baseline      0.396        1.000   0.271     0.333      0.4641
decay         0.404        0.417   0.196     0.750      0.4258
forgetting    0.412        0.417   0.000     0.750      0.4271
```

## 三、复用来源（acceptance 要求指明）

| 指标 | 实现位置 | 来源 |
|---|---|---|
| `precisionAtK` | `harness.ts` `measureWindow` → `precision` | 原 `bench/run-bench.ts`，逐字搬移 |
| `pinRecall` | 同上 → `pinRecall` | 同上 |
| `dupShare` | 同上 → `dupShare`（内部用 `isDuplicate`） | 同上 |
| 窗口内去重 | `harness.ts` `collapseDuplicates` | 原 `run-bench.ts` `forgetting` 分支的内联循环 |
| `evictedShare` | `src/planner.ts` `buildForgettingPlan` | 既有淘汰实现；`(archived + retired) / total` |

**没有复用 `bench/experiments.ts`**，理由是它强制 `--db` 且必须加载 Ollama embedding（`loadVectorIndex` + `embedWithOllama`）。网格扫描若依赖 embedding，同一张表里不同行的差别会混入"provider 当时是否在线"，而不是只反映参数。sweep 固定 lexical-only，可比基线是 `run-bench --no-embeddings`。

`clusterThreshold` 也进 `isDuplicate` 与 `measureWindow` 的签名（默认仍是 0.6），否则这六个参数里有一个扫不动。

## 四、命令示例

```bash
# 单点（默认值）——应与 run-bench 的 forgetting 行一致
node bench/sweep.ts --out sweep-default.csv

# 网格
node bench/sweep.ts --grid halfLifeDays=7,14,30,60 --grid floor=0.2,0.3 --out sweep.csv

# 两个网格交叉
npm run sweep -- --grid clusterThreshold=0.5,0.6,0.7 --grid archiveThreshold=0.35,0.45

# 真实快照
node bench/sweep.ts --corpus snapshot --db data/snapshot-20261026.db --queries 10 --out s.csv
```

`--grid` 可重复，笛卡尔积展开，第一个 flag 变化最慢。默认值从 `DEFAULT_DECAY` / `DEFAULT_CLUSTER_OPTIONS` / `DEFAULT_EVICTION` 读，不在 sweep 里另抄一份——D4 改默认值时自动跟随。

## 五、CSV 头

```
halfLifeDays,floor,minTrackingCoverage,clusterThreshold,archiveThreshold,retireThreshold,decayActive,precisionAtK,pinRecall,dupShare,evictedShare
```

六参数 + `decayActive`（`minTrackingCoverage` 的门开闭，不看它会误读另外两个参数的作用）+ 四指标。指标 4 位小数，参数原样，无千分位。

## 六、冒烟

| 场景 | 数据行 | 表头 | 耗时 | 备注 |
|---|---|---|---|---|
| 默认单点（synthetic，24 queries） | 1 | 1 | 232 ms | `precisionAtK=0.4125 pinRecall=0.7500 dupShare=0.0000 evictedShare=0.3582` |

## 七、跳过与退出码

| 情况 | 行为 | 退出码 |
|---|---|---|
| 参数值超出定义域（如 `floor=1.5`） | 跳过该组合，stderr 打原因，其余照跑 | 0 |
| `--grid` 语法错 / 未知键 / 非数值 | 命令本身不成立，立即报错 | 2 |
| 语料加载失败（如 `longtext` 未实现、snapshot 缺 `--db`） | stderr 报原因，不写 CSV | 1 |

`--corpus longtext` 现在**明确报错**而不是静默退回 synthetic：一行标着 longtext 却在短文本语料上测出来的数，事后没人查得出来。D2 补上生成器。

## 九、这一块没做的事

- **没有真实模型**：sweep 不碰 embedding，`experiments.ts` 那套语义口径未纳入。
- **没有跑满网格**：D1 只交付框架，参数敏感度区间是 D3。
- **`evictedShare` 是集合口径**：`(archived + retired) / total`，不区分两个通道；D3 若要分通道看，需要再拆列。
- **CI 未覆盖 sweep**：`.github/workflows/ci.yml` 只跑 `run-bench` 的回归门。是否把 sweep 加进 CI 属于 D4（改默认值时要对照）决定。
