## 改了什么

`src/applier.ts`：`auditSummary` 加了三个聚合（`actions` / `reasons` / `types`），`runs` 补了 `mode` 与 `actor`；新增 `auditRun(dbPath, runId, limit)` 和 `reasonKey(reason)`。

## 聚合口径

**理由聚类**：`reasonKey` 把 `\d+(\.\d+)?` 全部替换成 `#`。`score 0.312 < archive 0.45` 与 `score 0.298 < archive 0.45` 归为一类；`quota 100: bottom-ranked (1/5)` 变成 `quota #: bottom-ranked (#/#)`。这条规则原本只在 `renderPlan` 里有一份，现在两处共用同一个函数——分开写迟早会分叉，"最常见的理由"在两个视图里就会指不同的东西。

**按类型**：走 `forgetting_audit JOIN l1_records`。迁移前 `types` 为空对象，不报错。

**有界查询**：`forgetting_audit` 只增不删。三个聚合查询都是 `GROUP BY` 加 `LIMIT`（动作 100、理由 500、类型 50），`auditRun` 强制 `LIMIT`。`GROUP BY` 本身仍要扫表，这一点没法靠 LIMIT 解决——真正需要时应该加索引，现在没加，因为还没有证据说它慢。
