# LLM 判据落地记录（2026-11-04）

画布 C 的 `c6-llm-criteria` 把「哪条记忆已被新记忆取代」的判定交给模型，但把**证据采集**和**动手权**拆开。这份记录说的是拆开之后系统到底做了什么、哪些是实测出来的、哪些还没测。

## 1. 这个模块解决什么

C2 的 `supersede` 命令要求人给出 `--old`、`--new`、`--reason` 三个参数。822 条 L1 里人工挑矛盾对不现实，所以需要模型来提候选。但让模型直接写 `invalid_at` 是危险动作：判错一条，一条正确的记忆就静默地从召回里消失了。

所以模块被切成两半：

- `criteria` 用模型逐对判，判完只往 `forgetting_audit` 写 `llm-suggest` 行；
- 同一个命令加 `--mode=apply` 才会真写 `invalid_at`，而 apply 必须先过一道以**外部测量值**为准的门。

拆分点不是「先跑一会儿看看」，而是代码里一条硬边界：影子模式下那条 `UPDATE l1_records SET invalid_at = ...` 根本不会被执行到（`src/llm-criteria.ts` 的 `if (mode === "apply" && judged.verdict === "supersede")`，在该 run 的循环里 mode 是常量）。

## 2. 三判决而不是二判决

提示词 `src/prompts/supersede-judge.md`（`supersede-judge/v1`）要求模型输出三种之一：

- `supersede`：新记忆确实推翻了旧记忆；
- `keep-both`：两条都还成立（可能是同一件事的不同侧面）；
- `unrelated`：两条讲的不是一回事。

加 `unrelated` 是因为二选一里没有「这题不成立」的位置。要让模型在两条无关记忆间硬选，它会顺着「你是判取代的」这个框架倾向 `supersede`——这正是最坏方向的偏差。提示词还写了一行 `When unsure output keep-both`：不确定时倒向不写。

解析器（`parseVerdict`）容忍模型把 JSON 包在散文或代码围栏里，但对实质内容很严：**凡不是三个判决之一，一律返回 `null` 判决 + 错误，不做默认值**。默认成 `keep-both` 会让解析器坏了也看不出来。

## 3. 门禁的取证方向

`checkApplyGate(rate, reportPath)` 的方向是刻意选的：

| 输入 | 结果 |
|---|---|
| `rate` 缺失（`null`） | **拒绝**，exit 5 |
| `rate >= 0.05` | 拒绝，exit 5 |
| `rate < 0.05` | 放行 |

**没有测量值 = 拒绝**，不是当成 0。把「没测」当「0% 错误率」等于让模型自证清白。阈值 `LLM_APPLY_MAX_FALSE_SUPERSEDE = 0.05`。

测量值从命令行 `--false-supersede-rate` 进来，不从 run 内部算——一个模型不能靠自己这次的判得自信就给自己发许可。这条规则有代价：跑 apply 之前得先有人工标注。这个代价是要付的，因为反过来没有便宜的替代品。

## 4. 实测（影子 vs apply）

用一份本地 OpenAI 兼容 stub 当 judge（离线，不碰网络、不碰厂商），50 对 review set。stub 判出 **17 个 supersede**、33 个 keep-both。五组对照：

| 场景 | exit | `invalid_at` 非空行 | `llm-suggest` 行 | `invalidate` 行 |
|---|---|---|---|---|
| `--mode=shadow` | 0 | **0** | 50 | 0 |
| `--mode=apply` 无测量值 | **5** | 0 | 0 | 0 |
| `--mode=apply` 0.12 ≥ 0.05 | **5** | 0 | 0 | 0 |
| `--mode=apply` −0.5（非比率） | **5** | 0 | 0 | 0 |
| `--mode=apply` 0.00 | 0 | **17** | 50 | **17** |
| 同样 0.00 再跑一遍 | 0 | 17（无新增） | 100 | 17（无新增） |

第一行是这张表存在的理由：模型说了 17 次「取代」，库里 `invalid_at` 非空行数是 0。第二至四行的 0 是**拒绝发生在开库之前**——gate 不过就 return，连审计行都没写，所以这几行的 `llm-suggest` 也是 0。

第五行是反向对照：同样 50 对、同样 17 个 supersede 判决，过闸之后恰好写 17 行 `invalid_at`。所以第一行的 0 不是「模型没判出 supersede」，而是「影子没写」。

第六行是幂等性对照，也是评审逼出来的一处真 bug。第二次跑时 UPDATE 的 `AND invalid_at IS NULL` 匹配不到行，`changes = 0`，但原代码仍然无条件插 `invalidate` 审计行、把 id 塞进 `invalidated`、outcome 报 `applied: true`、CLI 打印 `[invalid_at WRITTEN]`。审计在这个项目里是唯一的纠错手段，一条"声称动作发生了、实际没发生"的行会把它废掉。现在按 `src/invalidation.ts:218-224` 的既有契约检查 `changes`，为 0 就什么都不写；CLI 改印 `[already invalid, nothing written]` 并单列一行 `already invalid before this run: N`。

> **一次数字返工。** 这节初稿写的是 7 个 supersede，配一份更早的 stub 规则。改规则后没重跑这张表，文档里的 7 与产物里的 17 对不上——独立评审指出的 major。返工时还发现第二个问题：旧 stub 按**请求序号**判决（`i % 3 === 0`），而每次 CLI run 都是新进程、计数器归零，于是 shadow 判的是第 0,3,…,48 对、apply 判的是第 1,4,…,49 对——两份报告的 supersede 集合**交集是 0/17**。数量同为 17 却完全不是同一批对，"同样 17 个判决"这句话当时是假的。现在 stub 按 pairId 排序后的稳定下标判决，实测两次 run 的 supersede 集合交集 17/17。

审计表里两种 action 分得开：`llm-suggest`（模型提的建议）和 `invalidate`（真的改了 `invalid_at`）。一周后回看，能分清哪些是模型说的、哪些是落地的。

实测环境：`E:\tdai-forgetting\.scratch\c6-lead\`，快照副本 `shadow.db` / `apply.db`（均从 `data/snapshot-20261026.db` 复制，原件按要求未动）。review set 由 `criteria --sample-from <db> --sample-size 50 --sample-out <path>` 生成，种子 `20261026`，同库同种子出同一份集合。

## 5. 采样带宽是被测量逼出来的

`samplePairs` 取「同场景内时间相邻、内容 3-gram jaccard 落在带内」的对，按 pairId 的 FNV-1a 加种子排序取前 N。

初版带宽是 `[0.12, 0.95]`，实测只捞到 37 对。把相邻对的相似度全测了一遍（479 对全部相邻对，中位数 0.049），发现带下限卡太死，放宽到 `[0.10, 0.90]` 后带内 63 对，取 50。

顺带修了 `cli.ts` 里输出给用户的那行采样规则说明——它写的是旧带宽。用户看到的规则文本和代码实际做的事必须一致，否则这份 review set 就没法被第三方复核。

## 6. 报告留痕

`--report <path>` 写一份 JSON，含 runId、模式、模型、提示词版本、配对总数、三判决计数、审计行数、被写列表、**以及 gate 拿到的那个测量值**。

数据是给第三方复核用的：review set 同库同种子可重放，所以报告是「可查」而不只是「可信」。

## 6.5 误标率：两位标注者，70.6% 与 88.2%

这一节返工过一次，返工的原因值得先说。

初版只有一位标注者——就是我（实现本块的 AI 代理）。独立评审判它不满足判据 6：**标注者是实现者**，那么"金标准"是自证的。这个批评成立，所以补了第二位标注者：一个独立子代理，只拿到 50 对的正文（`blind-pairs.json`，54 KB，不含任何既有标签），明确禁止读既有标注产物与本文档。它的产出是 `blind-labels.json`。

两位标注者的判决分布：

| | supersede | keep-both | unrelated |
|---|---|---|---|
| A1（实现者，AI） | 18 | 32 | 0 |
| A2（盲标，独立 AI） | 4 | 46 | 0 |
| stub judge | 17 | 33 | 0 |

**两位标注者的一致率只有 72.0%（36/50），Cohen's κ = 0.268。** κ 落在 "fair" 区间下沿。分歧全是同一个方向：A1 判 supersede 的 18 对里，A2 有 14 对判 keep-both。

误标率因此有两个值，取决于拿谁当金标准：

| 金标准 | true supersede | false supersede | 误标率 |
|---|---|---|---|
| A1（实现者） | 5 | 12 | **70.6%** |
| A2（盲标） | 2 | 15 | **88.2%** |
| 两者共识（36 对） | 2 | 12 | **85.7%** |

三个数都远高于 5% 的门槛，gate 会拒绝 apply——这是它该做的事。**但真正该读到的是标注者之间 72% 的一致率**：连"这条记忆是不是被取代了"这个判断本身，两个独立判断者有四分之一对不上。这意味着 5% 这个门槛在这份语料上可能根本无法稳定测量——不是判据不够好，是**任务本身的标注噪声比门槛还大**。

这不是给判据开脱，是给读数的人一个校准：拿一个 κ=0.27 的金标准去卡 5% 的门槛，卡出来的数字没有意义。要真正用这个门禁，得先让"什么算取代"在这份语料上有可复现的定义，或者把门槛换成"与人工共识相比不劣于 X"这种相对口径。

A2 报告的两处最难判的分歧正好说明问题：

- `m_1788887837760_3ab811e9__m_1788888256751_fc08779f`（RTD3 治本）：A2 判 supersede，原话「旧结论为 RTD3 治本未落地（参数仍为 3、无覆盖文件），新记已写入 conf 并重建 initramfs，状态被推翻。」A1 也判 supersede，原话「同一 RTD3 事项的核查（未落地）与落地，后者取代前者的状态」。**这一对两人一致，但一致得很脆**：旧记忆本身还带着当时有效的取证细节（独显直连拓扑、persistenced 勘误、RTD3 不写内核日志），判 supersede 后这些旁证就只剩在被标记的那一行里了。三判决里没有「取代但保留取证」这个位置。
- `m_1791542522086_166eb08e__m_1791542522086_07deb746`（期刊排序）：A2 判 keep-both，原话「旧是含金量单轴定谳（冲刺 DT/JFE、主线农工学报+JFPE），新追加稳定性×含金量双轴表，DT/JFE 改为彩票组属细化而非否证。」A1 也判 keep-both，原话「同一排序研究的第五轮与第六轮，轴不同」。两人一致，但这条离 supersede 只有一线——「细化」与「改写口径」的边界本身模糊。

标注产物与复算材料都在受控目录 `docs/experiments/c6-criteria-eval/`（进版本库；`.scratch/` 被 gitignore，放那里等于新克隆复算不了）：

| 文件 | 内容 |
|---|---|
| `review-set.json` | 50 个 pairId + 抽样规则 + 种子（**无正文**：仓库公开，记忆是个人数据） |
| `human-labels.json` | A1 的 50 对判决 + 逐对理由 + set 级 labelledBy/labelledAt |
| `blind-labels.json` | A2 的 50 对判决 + 逐对理由 |
| `merge-labels.mjs` | 把 A1 标签并进 review set |
| `stub-judge.mjs` | 离线 stub judge（按 pairId 排序后的稳定下标判决） |
| `report-to-verdicts.mjs` | criteria 报告 → `--verdicts` 输入 |
| `agreement.mjs` | 一致率、Cohen's κ、三套误标率 |
| `census.mjs` | 数 `invalid_at` 非空行与审计表分组 |
| `regen.ps1` | 一条命令跑完全部实测 |
| `measure-report.json` | 提交在库里的那份机器判决——**不用数据库、不用端点**也能从它 + 两份标注复算出误标率 |
| `evaluation.json` / `agreement.json` | 当前结果 |
| `README.md` | 为什么这里没有正文，以及怎么用这些脚本 |

运行产物（`review-set-labelled.json`、`measure-report.json`、`verdicts.json`）落在 `-Work` 指定的目录，默认 `.scratch/c6-lead/`，不会写回 `docs/`。

**两位标注者都是 AI 代理，不是人类领域专家。** 字段如实写的是 `lead-agent (DeepSeek-V4.1-Flash, dsh session)` 与 `second-annotator (independent agent, no access to prior labels)`。第二个虽然没看到第一个的答案，但它和第一个是同一个底层模型——所以 72% 的一致率**不能**解读为"人类标注者之间大概也有 72% 一致"。它只能说明：**连同一个模型的两次独立判断都有 28% 的分歧**。真人标注的一致性可能更高也可能更低，得实际测。

这个数足以证明两件事：门禁方向正确（无论取哪个金标准都远高于门槛，apply 会被挡住）；以及**5% 这个门槛在当前标注质量下不可测量**。它不足以证明判据的真实水平。真跑 apply 之前必须由人来标一遍，并且至少要两位人类标注者来算 κ。

## 6.6 报告落盘

`--report <path>` 在 `criteria` 与 `criteria-eval` 上都写 JSON：

- `criteria`：runId、模式、模型、提示词版本、配对总数、三判决计数、审计行数、被写列表、**gate 拿到的那个测量值**、逐对判决。
- `criteria-eval`：review set 版本、采样规则、标注者与标注时间、混淆矩阵与误标率。

改动前这两处 `--report` 都只被当作 gate 的入参读过、从没落盘，而 usage 里写着"Where to write the run report"。已补实现。

数据是给第三方复核用的：review set 同库同种子可重放，报告里的判决可转成 `--verdicts` 重算，所以这个数是「可查」而不只是「可信」。

## 7. 还没做的

- **没有真实模型跑过。** 本机 Ollama 只有 `bge-m3`（embedding，不是 chat 模型），也没配 `OPENAI_API_KEY`。测试全部用注入的 fake provider，实测用本地 stub。换真实模型要拉多 GB 权重，这是要阁下拍板的事，没自作主张。
- **没有人类标注。** 见 6.5：两位标注者都是 AI 代理。三位数的误标率证明门禁会挡住坏判据，但 5% 这个门槛在 κ=0.27 的标注质量下不可测量。
- **门槛的口径可能要改。** 若「取代」在这份语料上本来就存在大量真实歧义，绝对阈值 5% 就不合适。相对口径（比基线判据好多少）或分层口径（按 `type` / `scene` 分开设阈）可能更实际。这是设计决策，没在本块内擅自改。
- **判据端点故意没有默认值。** `--judge-url` / `--judge-model` 不填就报错退出。哪个模型读你的记忆是部署决策，悄悄给个默认端点等于替用户选了别人家的模型。

## 8. 复现

全部脚本在受控目录 `docs/experiments/c6-criteria-eval/` 里，路径都相对脚本自身，换机器不用改。环境是 Windows / PowerShell（仓库的实际验收环境，本机是 Windows PowerShell 5.1，没有 `pwsh`）。

### 8.1 一条命令跑完全部实测

需要一份 `data/snapshot-20261026.db`（不进版本库，见 `.gitignore`）。脚本自己复制副本，原件只读：

```powershell
cd E:\tdai-forgetting
& docs\experiments\c6-criteria-eval\regen.ps1
# 换输出目录：
& docs\experiments\c6-criteria-eval\regen.ps1 -Work .scratch\my-run
```

它会依次打印七个场景的 exit code、两个库的 census、四份报告的摘要，最后是误标率与 κ。预期：

| 场景 | exit | 说明 |
|---|---|---|
| shadow | 0 | `invalid_at` 一行不写 |
| apply 无测量值 | 5 | 拒绝发生在开库之前 |
| apply 0.12 | 5 | 超阈 |
| apply −0.5 | 5 | 不是比率 |
| apply 空值 `--false-supersede-rate=` | 5 | 空的不是 0 |
| apply 0.00 | 0 | 写 17 行 |
| 再跑一遍 0.00 | 0 | 打印 `already invalid before this run: 17`，不新增审计行 |

census 预期：shadow 库 `invalid_at 0` / `llm-suggest 50`；apply 库 `invalid_at 17` / `invalidate 17` / `llm-suggest 100`。末尾应打印 `72.0%, kappa = 0.268` 与 70.6% / 88.2% / 85.7%。

`regen.ps1` 跑完会 `Stop-Job` 关掉它自己起的 judge，所以 **`$url` 不会留在你的 shell 里**。要分步跑 8.2，按 8.3 自己起一个并保留。

### 8.2 复算误标率与一致率

两种路子。**先看不需要数据库和端点的那种**，它只吃已提交在库里的证据：

```powershell
cd E:\tdai-forgetting
$ev = "docs\experiments\c6-criteria-eval"
$w  = ".scratch\c6-lead"
New-Item -ItemType Directory -Force -Path $w | Out-Null

# 直接用提交在库里的 measure-report.json，不跑任何 judge
node "$ev\agreement.mjs" --measure "$ev\measure-report.json" --out $w
```

输出即下面那五行。这条路把「机器判决」也换成了受控目录里的副本，所以它验的是 **标签与算式的自洽**，不是这次运行的新鲜度。要验新鲜度走下面这条。

完整链路（需要一个活着的 judge，见 8.3）：

```powershell
cd E:\tdai-forgetting
$ev = "docs\experiments\c6-criteria-eval"
$w  = ".scratch\c6-lead"
New-Item -ItemType Directory -Force -Path $w | Out-Null
Copy-Item data\snapshot-20261026.db "$w\measure.db" -Force

# a) 把 A1 标注并进 review set，产出到 $w（不写回 docs/）
node "$ev\merge-labels.mjs" $w

# b) 在带标注的集合上跑一遍 judge（$url 来自 8.3，必须还在跑）
node --experimental-strip-types src/cli.ts criteria `
  --db "$w\measure.db" --pairs "$w\review-set-labelled.json" `
  --judge-url $url --judge-model stub-1 `
  --mode shadow --report "$w\measure-report.json"

# c) 报告 -> --verdicts 输入
node "$ev\report-to-verdicts.mjs" "$w\measure-report.json" "$w\verdicts.json"

# d) 混淆矩阵与误标率（criteria-eval 不需要 --db）
node --experimental-strip-types src/cli.ts criteria-eval `
  --set "$w\review-set-labelled.json" `
  --verdicts "$w\verdicts.json" --report "$w\evaluation.json"

# e) 两位标注者的一致率、Cohen's kappa、三套误标率
#    标注固定从 docs 读；机器判决用刚跑出来的那份，才是在检查而不是自证
node "$ev\agreement.mjs" --measure "$w\measure-report.json" --out $w
```

第 (e) 步预期输出：

```
A1 (implementer):        {"supersede":18,"keep-both":32,"unrelated":0}
A2 (blind, independent): {"supersede":4,"keep-both":46,"unrelated":0}
judge supersede calls:   17

inter-annotator agreement: 36/50 = 72.0%, kappa = 0.268
confusion (A1|A2): {"supersede|keep-both":14,"keep-both|keep-both":32,"supersede|supersede":4}

false-supersede vs A1:                   12/17 = 70.6%
false-supersede vs A2:                   15/17 = 88.2%
false-supersede vs consensus (36 pairs):  12/14 = 85.7%
```

注意 `agreement.mjs` 的输入分工：标注固定读受控目录里的两份，机器判决用 `--measure` 指向刚跑出来的那份，`--out` 不给就不落盘。**重算覆盖受控证据，等于用同一份产物证明自己**——这条路径被刻意掐掉了。

### 8.3 起一个 stub judge 并保留

要把 8.2 分步跑完，judge 得活到你跑完最后一步。它的两个输出（URL 文件、判决日志）写进 `$w`，不写受控目录：

```powershell
cd E:\tdai-forgetting
$ev = "docs\experiments\c6-criteria-eval"
$w  = ".scratch\c6-lead"
New-Item -ItemType Directory -Force -Path $w | Out-Null

$judge = Start-Job -ScriptBlock {
  param($d, $o) Set-Location $d
  node (Join-Path $d "stub-judge.mjs") (Join-Path $d "review-set.json") (Join-Path $o "judge-url.txt") (Join-Path $o "stub-verdicts.json")
} -ArgumentList (Resolve-Path $ev).Path, (Resolve-Path $w).Path
Start-Sleep -Seconds 2
```
