# 参数敏感度 — 2026-11-06（第二轮：当前代码）

> **这是重跑版。** 第一版跑在 D4 改默认值、D5 改长文本算法**之前**，那批数据已经不对应当前代码，报告里挂着"时效性"警告。现在按当前代码重跑，结论有两处实质变化，见第零节。

画布 D 的 D3。六个参数，一次只动一个（OAT），三份语料各扫一遍。数据全部来自 `bench/sweep.ts` 的 CSV，没有手算的数字。

## 怎么测的

```
node bench/sweep.ts --grid <参数>=<值,...> --out <csv>                              # synthetic
node bench/sweep.ts --corpus longtext --grid ... --out <csv>                        # longtext
node bench/sweep.ts --corpus snapshot --db data/snapshot-20261026.db --grid ... --out <csv>
```

- 检索固定 lexical-only，指标口径与 `bench/run-bench.ts` 的 `forgetting` 配置同源。
- 每组参数重跑一次 `buildForgettingPlan`，`evictedShare = (archived + retired) / total`。
- 语料特征见 [三语料特征](./三语料特征-2026-11-06.md)。

## 零、重跑后变了的两件事

### 1. `archiveThreshold` 不再是死参数 —— 因为 floor 把分数下界拉下来了

第一版说它"在三份语料上扫出满屏平线，因为分数下界高于阈值"。那是对的，但下界**会随参数移动**：

| | 分数下界（minScore） | `archiveThreshold` 0.45 是否命中 |
|---|---|---|
| 第一版（floor 0.3） | **0.471** | 否，一条都没有 |
| 当前（floor 0.2） | **0.401** | 是，synthetic 83 条 |

公式决定的：无 usage 信号时，`(0.4 × importance + 0.3 × floor) / 0.7`，importance 最低 0.55 → floor 0.3 时 0.471、floor 0.2 时 0.401。**D4 把 floor 降到 0.2，等于把绝对阈值的生效线也拉低了 0.07。**

所以现在是：`archiveThreshold` 在 **0.35–0.40 仍平**（在下界以下），**0.45 起开始命中**，0.5 时 synthetic 归档 43.4%。

顺带证实了归档的构成：

| clusterThreshold | archiveThreshold | 总归档 | 按分数 | 按冗余 |
|---|---|---|---|---|
| 0.6 | 0.45 | 295 | 83 | 212 |
| 0.7 | 0.45 | 237 | 83 | 154 |
| 0.7 | 0.35 | 183 | **0** | 183 |

**按分数归档的条数与 clusterThreshold 无关**（都是 83），按冗余归档的条数才随它变。两个参数各管一段，但在总数上叠加——这就是第一版把 `archiveThreshold` 误判成死参数的原因：当冗余归档占了 250 条、把总数撑起来时，绝对阈值那 0 条的变化被淹没了。

### 2. `clusterThreshold` 对长文本彻底失效

D5 把超过 400 字的记录改成按**块覆盖率**比较，那两个门槛是 `blockSimilarity` / `blockCoverage`（都是 0.8），**不看 `threshold`**。所以 longtext 的 `evictedShare` 在 `clusterThreshold` 0.4–0.8 之间**恒为 0.5500**：

```
0.4:0.55  0.5:0.55  0.6:0.55  0.7:0.55  0.8:0.55
```

短文本照旧受它控制（synthetic 0.4 时 0.9355）。**同一个参数在两类语料上是两套机制**，调它之前要先知道语料里长文本占多少。

## 一、halfLifeDays（最影响 pinRecall）

| 值 | synthetic precision | synthetic pinRecall | longtext precision | longtext pinRecall |
|---|---|---|---|---|
| 7 | 0.4364 | **0.8333** | 0.2333 | **0.5000** |
| 14 | 0.4090 | **0.8333** | 0.2500 | **0.5000** |
| 30 | 0.4044 | 0.7917 | 0.2500 | 0.4444 |
| 45 | 0.4124 | 0.7083 | 0.2556 | 0.3889 |
| 60 | 0.4173 | 0.6250 | 0.2667 | 0.3333 |
| 90 | 0.4621 | **0.4583** | 0.2722 | 0.3333 |

**区间结论：7–14 天之间 pinRecall 不变（0.833 / 0.500），越过 15 天开始下降，90 天时 synthetic 掉到 0.458。** 同时 precision 从 0.409 升到 0.462——这不是"越久越好"，是**拿 pin 召回换 topical precision**。

snapshot 全平（`decayActive` 恒 false）。

D4 选的默认值 10 落在平台中间，不是边缘。

## 二、floor（现在直接决定归档量）

| 值 | synthetic precision | synthetic pinRecall | synthetic evictedShare | longtext evictedShare |
|---|---|---|---|---|
| 0.1 | 0.4105 | 0.8333 | **0.4155** | **0.6083** |
| 0.2 | 0.4137 | 0.8333 | 0.3395 | 0.5500 |
| 0.3 | 0.4165 | 0.8333 | 0.2679 | 0.5083 |
| 0.4 | 0.4433 | 0.8333 | 0.2622 | 0.4917 |
| 0.5 | 0.4482 | 0.8333 | 0.2622 | 0.4917 |

**区间结论：floor 在 0.1–0.3 之间 precision 几乎不动（0.411–0.417），但 `evictedShare` 一路从 0.4155 降到 0.2679；0.4 起 precision 开始上升且归档量见底。**

这一版和第一版最大的差别就在这里：pinRecall 在 synthetic 上**全程 0.8333 不动**（第一版会从 0.792 掉到 0.625）。原因同上——D4 之后 floor 的下界已经够低，再抬 floor 的边际影响落在别处了。**floor 现在是控制归档量的旋钮，不是控制 pin 召回的。**

0.5 时 longtext 的 pinRecall 从 0.5000 掉到 0.4444，这是唯一一处它在伤害 pin。

## 三、minTrackingCoverage（不是连续敏感，是开关）

| 值 | synthetic | longtext | snapshot |
|---|---|---|---|
| 0 | decay=true, prec 0.4137, pin 0.8333 | decay=true, 0.2500 / 0.5000 | decay=true, **0.1042** |
| 0.05 | 同上 | 同上 | decay=false, **0.2375** |
| 0.10 | 同上 | 同上 | decay=false, 0.2375 |
| 0.20 | 同上 | 同上 | decay=false, 0.2375 |
| 0.40 | decay=false, **0.4846** / **0.2083** | decay=false, 0.2333 / **0.1111** | decay=false, 0.2375 |

**区间结论：在语料 coverage 之上，阈值怎么调都不变；一旦越过语料 coverage，`decayActive` 翻转，指标一次跳变到位。** synthetic 的 coverage 是 29.9%，longtext 33.3%，snapshot 0%。

snapshot 那两行是这个参数唯一被数据证明的价值：强制开门（`=0`）时 precision **0.1042**，关门 0.2375 —— **白丢 13.3 个点**。比第一版的 7.9 个点更糟，因为 `archiveThreshold` 现在会命中，开门的代价传到了归档上（`evictedShare` 0.0073 而不是 0）。

这个参数没有"阈值区间"，只有"开关位置"。默认 0.1 落在无差异区间中间，没有理由动。

## 四、clusterThreshold（短文本最脆，长文本失效）

| 值 | synthetic evictedShare | synthetic precision | longtext evictedShare |
|---|---|---|---|
| 0.4 | **0.9355** | 0.4205 | 0.5500 |
| 0.5 | 0.7937 | 0.4652 | 0.5500 |
| 0.6 | 0.4226 | 0.4210 | 0.5500 |
| 0.7 | 0.3395 | 0.4137 | 0.5500 |
| 0.8 | 0.2908 | 0.4166 | 0.5500 |

**区间结论（短文本）：0.4 是悬崖——93.6% 的记录被冗余合并吞掉；0.5 仍有 79.4%；越过 0.6 往上每 0.1 稳定减少约 7–9 个点。**

**区间结论（长文本）：0.4–0.8 之间完全无影响**，因为块级路径不看这个阈值。长文本的重复判定由 `blockSimilarity` / `blockCoverage` 控制，而那两个参数**没有做过敏感度扫描**——这是本节留下的缺口。

0.5 时 synthetic 的 precision 反而是最高的（0.4652），代价是 79.4% 的语料被归档。第一版的判断仍然成立：最优点落在悬崖边上，不能选。

## 五、archiveThreshold（0.45 起才生效）

| 值 | synthetic evictedShare | longtext evictedShare | snapshot evictedShare |
|---|---|---|---|
| 0.35 | 0.2622 | 0.4917 | 0.0000 |
| 0.40 | 0.2622 | 0.4917 | 0.0000 |
| 0.45 | **0.3395** | **0.5500** | 0.0000 |
| 0.50 | **0.4341** | **0.6167** | 0.0000 |

**区间结论：0.35–0.40 完全平（在分数下界 0.401 以下，一条都命中不了），越过 0.40 后每 0.05 增加 7–10 个点归档。**

precision / pinRecall 在所有取值上**完全不变**——归档是事后动作，不改检索排序。所以这个参数的唯一效应就是"归档多少"，评价它好不好得看归档质量，而不是看这两个指标。

snapshot 到 0.5 仍为 0：它的分数下界是 0.550（decay 关着，分数只由 importance 和 usage 决定）。

## 六、retireThreshold（仍然是死参数）

| 值 | synthetic evictedShare | longtext evictedShare | snapshot |
|---|---|---|---|
| 0.15 | 0.3395 | 0.5500 | 0.0000 |
| 0.20 | 0.3395 | 0.5500 | 0.0000 |
| 0.25 | 0.3395 | 0.5500 | 0.0000 |
| 0.30 | 0.3395 | 0.5500 | 0.0000 |

**区间结论：0.1–0.45 之间完全无影响。**

原因是硬的：它对每个记录要求 `score < retireThreshold` **且** `age >= minAgeDays(14)`，而三份语料的分数下界是 0.401 / 0.407 / 0.550，**全都高于 0.30**。这个区间里没有任何记录能被判定为 retire。

第一版补扫过 0.5 以上（那时能看到 retired 出现），但**那是 floor 还是 0.3 的时候**。当前代码下 retire 要生效也得越过 0.401，而且生效之后它只是把本该归档的记录改判成退休，`evictedShare` 不变——**它对总量没有影响，只对分类有影响**，而 CSV 里没有单独的 retired 列。这是 D4 遗留的测量口径问题。

## 哪个最脆，哪个最不敏感

**最脆：`clusterThreshold`（仅短文本）。** `evictedShare` 量程 0.645（0.2908–0.9355），其余参数没有超过 0.18 的。而且它错了的代价最大——0.4 时吞掉 93.6% 的语料。

**最不敏感：`retireThreshold`。** 量程 0.000，全部区间无影响。

**最被误解：`archiveThreshold`。** 第一版判它是死参数，重跑后它有 0.172 的量程。差别的来源不是代码变更本身，是 floor 把它前面的地板拉低了。**"某个参数扫了没差异"这句话有时效性。**

## 一句话

当前代码下：`clusterThreshold` 只对短文本有杀伤力（长文本归块级路径管，而那两个门槛没扫过）；`halfLifeDays` 和 `floor` 在拿 pinRecall / 归档量做交换；`minTrackingCoverage` 是开关不是旋钮；`archiveThreshold` 从 0.45 起才真正参与决策；`retireThreshold` 在这个区间里一次都没被触发。
