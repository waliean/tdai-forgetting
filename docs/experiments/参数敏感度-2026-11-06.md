# 参数敏感度 — 2026-11-06

画布 D 的 D3。六个参数，一次只动一个（OAT），三份语料各扫一遍。数据全部来自 `bench/sweep.ts` 的 CSV，没有手算的数字。

## 怎么测的

```
node bench/sweep.ts --grid <参数>=<值,...> --out <csv>                              # synthetic
node bench/sweep.ts --corpus longtext --grid ... --out <csv>                        # longtext
node bench/sweep.ts --corpus snapshot --db data/snapshot-20261026.db --grid ... --out <csv>
```

- 检索固定为 lexical-only（`bench/harness.ts`），指标口径与 `bench/run-bench.ts` 的 `forgetting` 配置同源。
- 每组参数都重新跑一次 `buildForgettingPlan`，`evictedShare = (archived + retired) / total`。
- 语料特征见 [三语料特征](./三语料特征-2026-11-06.md)。

先给一条会误导人的前提。

## 零、两个绝对阈值在三份语料上都是"死参数"

`archiveThreshold` 和 `retireThreshold` 的扫描在 0.1–0.5 / 0.1–0.3 区间内**完全是平线**。这不是它们不敏感，是**没有任何记录落在阈值里**：

| 语料 | 分数 p10 | min | archiveThreshold 默认 0.45 |
|---|---|---|---|
| synthetic | 0.537 | **0.471** | 够不到 |
| longtext | 0.530 | **0.485** | 够不到 |
| snapshot | 0.800 | **0.550** | 够不到 |

分数下界由公式决定：`importanceWeight 0.4 × importance(最低 0.55) + decayWeight 0.3 × floor(最低 0.3)`，除以权重和 1.0，就是 0.31 左右；实际语料的 priority 分布把下界抬到 0.47–0.55。

后果是 synthetic 的 250 条归档**全部来自 Pass 2（冗余）**，没有一条来自 Pass 1（绝对阈值）。这也解释了为什么把 `archiveThreshold` 从 0.45 降到 0.1，`evictedShare` 一动不动。

所以下面两节的区间是从 0.45 往上补扫出来的，不是 impl 指定的网格。

## 一、halfLifeDays（最影响 pinRecall）

| 值 | synthetic precision | synthetic pinRecall | longtext precision | longtext pinRecall |
|---|---|---|---|---|
| 7 | 0.4417 | **0.8333** | 0.2469 | **0.5000** |
| 14 | 0.4085 | **0.8333** | 0.2525 | 0.5000 |
| 30 | 0.4125 | 0.7500 | 0.2519 | 0.3889 |
| 45 | 0.4241 | 0.6250 | 0.2667 | 0.3333 |
| 60 | 0.4491 | 0.5000 | 0.2611 | 0.3333 |
| 90 | 0.4695 | **0.4583** | 0.2667 | 0.3333 |

**区间结论：7–14 天之间 pinRecall 不变（0.833），越过 30 天后开始下降，到 90 天时从 0.833 掉到 0.458，掉了 45%。** 与此同时 precision 从 0.409 升到 0.470——这不是"半衰期越长越好"，是**用 pin 召回换 topical precision**。snapshot 上全平（`decayActive` 恒 false）。

这一条直接质疑默认值 30：默认值落在 pinRecall 开始下滑的拐点正上方。

## 二、floor（影响较小）

| 值 | synthetic precision | synthetic pinRecall | longtext precision | longtext pinRecall |
|---|---|---|---|---|
| 0.1 | 0.3997 | 0.7917 | 0.2519 | 0.4444 |
| 0.2 | 0.4107 | 0.7917 | 0.2519 | 0.4444 |
| 0.3 | 0.4125 | 0.7500 | 0.2519 | 0.3889 |
| 0.4 | 0.4263 | 0.7083 | 0.2574 | 0.3889 |
| 0.5 | **0.4567** | 0.6250 | **0.2722** | 0.3333 |

**区间结论：0.1–0.3 之间指标基本不动，越过 0.4 后 precision 上升、pinRecall 下降，0.5 时两者分别是 0.457 / 0.625。** 方向和 halfLifeDays 一样：把衰减压平，topical precision 涨，pin 召回掉。默认值 0.3 落在稳定区内侧。

## 三、minTrackingCoverage（不是连续敏感，是开关）

| 值 | synthetic | longtext | snapshot |
|---|---|---|---|
| 0 | decay=true, prec 0.4125, pin 0.7500 | decay=true, 0.2519 / 0.3889 | decay=true, **0.1588** / 1.0000 |
| 0.05 | 同上 | 同上 | decay=false, **0.2380** / 1.0000 |
| 0.10 | 同上 | 同上 | decay=false, 0.2380 |
| 0.20 | 同上 | 同上 | decay=false, 0.2380 |
| 0.40 | decay=false, **0.4826** / **0.2083** | decay=false, 0.2333 / **0.1111** | decay=false, 0.2380 |

**区间结论：在语料 coverage 之上，阈值怎么调都不变；一旦阈值越过语料 coverage，`decayActive` 翻转，指标一次跳变到位。** synthetic 的 coverage 是 29.9%，longtext 33.3%，snapshot 0%，所以同一个 0.4 在 synthetic/longtext 上关门、在 snapshot 上不关门；而同一个 0.05 在 snapshot 上就已经关门。

最关键的一行是 snapshot：`minTrackingCoverage=0`（强制开门）时 precision 0.1588，`≥0.05`（关门）时 0.2380。**在没有任何访问数据的语料上，开衰减白丢 7.9 个点。** 这正是 `10%` 门槛存在的理由，也是它唯一在数据上被证明的价值。

这个参数没有"阈值区间"，只有"开关位置"。

## 四、clusterThreshold（最脆）

| 值 | synthetic evictedShare | synthetic precision | longtext evictedShare |
|---|---|---|---|
| 0.4 | **0.9355** | 0.4343 | **0.8167** |
| 0.5 | 0.7779 | 0.4645 | 0.0000 |
| 0.6 | 0.3582 | 0.4125 | 0.0000 |
| 0.7 | 0.2622 | 0.4062 | 0.0000 |
| 0.8 | 0.1920 | 0.4083 | 0.0000 |

**区间结论：0.4 是一个悬崖。** synthetic 上阈值降到 0.4，冗余聚类吞掉 93.6% 的记录（默认 0.6 时是 35.8%）；longtext 上从 0 直接跳到 81.7%。越过 0.5 往上则每 0.1 稳定减少约 7 个点。

这是六个参数里唯一能把 `evictedShare` 推开 0.7 以上的。也是唯一一个**错了会真的删掉大部分语料**的参数。默认值 0.6 距离悬崖只有 0.1 的余量。

注意 longtext 的 0.8167 不是"聚类正常工作"：长文本的 brief/full 在 0.6 下检不出（见三语料报告），把阈值压到 0.4 才开始把不同事实也吞进去。低阈值的代价在长文本上比在短文本上更早出现。

## 五、archiveThreshold（扫描区间内无影响）

补扫（`retireThreshold` 固定 0.1）：

| 值 | synthetic archived | synthetic evictedShare | longtext archived | snapshot archived |
|---|---|---|---|---|
| 0.1–0.47 | 250 | 0.3582 | 0 | 0 |
| 0.48 | 255 | 0.3653 | 0 | 0 |
| 0.50 | 264 | 0.3782 | 8 | 0 |
| 0.55 | 302 | 0.4327 | 14 | 0 |
| 0.60 | 348 | 0.4986 | 30 | 1 |

**区间结论：在 0.1–0.47 之间结论完全不变（平线），越过 0.48 后每 0.05 增加约 5–7 个点的归档，0.6 时 synthetic 有 49.9% 的语料被归档。** snapshot 到 0.55 都还是 0，因为它的分数下界 0.55 最高。

默认值 0.45 落在平线区**内侧**——它比语料的最低分还低，等于这个参数当前不起作用。

## 六、retireThreshold（同样在区间内无影响）

| 值 | synthetic archived / retired | synthetic evictedShare | longtext archived / retired |
|---|---|---|---|
| 0.10–0.45 | 250 / 0 | 0.3582 | 0 / 0 |
| 0.50 | 239 / 25 | 0.3782 | 0 / 8 |
| 0.55 | 211 / 91 | 0.4327 | 0 / 14 |
| 0.60 | 161 / 184 | 0.4943 | 0 / 30 |

**区间结论：0.1–0.45 之间结论完全不变，越过 0.5 后开始有记录进入 retire 分类，0.6 时 synthetic 有 26.4% 被 retire。**

这里还暴露出一个**测量口径问题**：`evictedShare` 把 archive 和 retire 合并计数，所以 retire 阈值变化时它只反映"总数变了"，不反映"分类从 archive 转到了 retire"。上表里 `retire=0.6` 时 archived 从 250 降到 161、retired 从 0 升到 184，而 `evictedShare` 只从 0.3582 变到 0.4943。要单独看 retire 的影响，得看 `retired` 列，CSV 里没有。这是 D4 之前需要决定的一件事：要么加一列，要么承认这个参数只能靠 planner 的原始输出评。

## 哪个最脆，哪个最不敏感

**最脆：`clusterThreshold`。** `evictedShare` 的量程 synthetic 0.744、longtext 0.817，其余五个参数没有一个超过 0.09。而且它错了的代价最大——0.4 时吞掉 82–94% 的语料。

**最不敏感：`archiveThreshold` 与 `retireThreshold`。** 扫完 impl 指定的整个区间，量程是 0.000。

但这两个"最不敏感"要打个折：它们的平不是"参数稳健"，是"扫的区间整个落在语料的分数下界以下"。补扫到 0.5 以上立刻有反应。**把它们的默认值留在 0.45 / 0.25，等于把这两个参数留着不用。**

## 一句话

六个参数里只有 `clusterThreshold` 和 `minTrackingCoverage` 能在现有语料上把指标推开（一个靠悬崖，一个靠开关）；`halfLifeDays` 和 `floor` 在做 precision 与 pinRecall 的交换；两个绝对阈值参数在默认值附近完全没有可观测效果，因为三份语料的分数下界（0.47–0.55）全都高于它们。
