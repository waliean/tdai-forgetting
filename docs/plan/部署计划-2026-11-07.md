## 一、P0：0105 的部署顺序 bug —— 已修（0106）

`0105` 加了 `CREATE INDEX ... l1_records(invalid_at)`，**没有 try/catch**；而五份补丁里**没有一份创建 `invalid_at` 列**——只有本仓库 `src/migrate.ts` 创建它，容器从不调用那个文件。

在真实生产库副本上按代码顺序复现：

```
stock: state = false | invalid_at = false
after 0101 ALTERs: has state = true | has invalid_at = false
0105 CREATE INDEX threw: no such column: invalid_at
=> initSchema THROWS -> VectorStore 进入 degraded 模式（全 no-op，进程仍 healthy）
```

第二层：`CREATE VIEW ... invalid_at IS NULL` 在 SQLite 里**建时不校验**，`SELECT` 才报 `no such column`。

### 已交付 `patches/0106-l1-invalidate-columns.patch`

- 两条**带 try/catch** 的 `ALTER TABLE ADD COLUMN invalid_at / superseded_by`，写在 0105 的 index 之前；
- 把 0105 那条未保护的 index 也包进 try/catch；
- 在副本上验证：`0106 invalidation DDL: OK` / `SELECT from l1_recallable: OK, rows = 859` / 重跑命中守卫。

## 三、P3：换嵌入 provider —— 实测结论

生产原本用 Ollama 的 `bge-m3`（1024 维），模型已丢。

**已实测的三条路：**

| 方案 | 结果 |
|---|---|
| `www.autodl.art` 的 `/v1/embeddings` | **不可用**。42 个模型全是 chat/图像，无 embedding；`/embeddings` 端点直接 404 |
| Ollama 拉回 `bge-m3` | 未测（体积约 1.2 GB，阁下已选"换 provider"） |
| **Ollama 拉 `mxbai-embed-large`** | **已拉取，1024 维，与生产向量维度一致** |

`mxbai-embed-large` 的关键好处：**维度 1024 与生产 `embedding_meta` 记录的 `bge-m3/1024` 相同**。这意味着切换后 `dimensions` 一项不变，`initSchema` 的 provider/model 变更检测虽然仍会触发 `dropVectorTables()` + `needsReindex: true`，但不会因为维度变化而让旧向量变成另一种形状的垃圾。

**必须先读的机制**（`memory-store.ts:433-455`）：`savedMeta.provider !== providerInfo.provider` 或 `model` 不同时，会**丢弃全部向量表**并返回 `needsReindex: true`。而 `reindexAll()` **没有任何自动调用点**——只有定义（`memory-store.ts:617/2303/1848`）和仓库里那个手工脚本 `rebuild-tdai-vectors.js`。

**所以换 provider 的完整代价是：全部 556 条 L1 向量会被丢弃，然后必须手工跑一次重嵌入，否则向量通道一直是空的。** 这一步不做，"归档不可召回"的验证只能测 FTS 过滤。

改动落点（`.env` 与 `start-memory-core.sh` 生成的 `tdai-gateway.yaml`）：

```yaml
embedding:
  provider: openai
  baseUrl: http://host.docker.internal:11434/v1
  model: mxbai-embed-large     # 原 bge-m3
  dimensions: 1024
```

另需：`ollama pull mxbai-embed-large`（**已拉取**，669 MB），并确认容器内 `host.docker.internal:11434` 可达（此前 `bge-m3` 就是这么配的，理论上通）。

## 五、P4：两个新引入的"拍的数"

D5 引入的 `blockSimilarity` / `blockCoverage`（都 0.8）控制所有 >400 字的重复判定，**从没扫过敏感度**。`clusterThreshold` 对长文本已完全失效，这两个成了长文本唯一的旋钮。

做法与 D3 相同：加进 `bench/sweep.ts` 的 grid，在 longtext 上扫，看 `evictedShare` 与真重复召回/误合并。约半天，产出并入 D3 报告。
